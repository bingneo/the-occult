开发需求：实验失误大屏（展示墙） - 搞笑风格 + 支持发布入口
1. 目标：
为用户提供一个幽默、轻松的空间，分享和浏览实验失败故事。用户可以在该页面发布自己的失败故事，查看其他人的失败经历，通过点赞、评论和社交分享功能，增强平台的趣味性和社交互动。
2. 需求：
2.1 数据库设计：
failures 表（用于存储失败故事）：
id（主键，自增）
user_id（外键，关联用户）
title（失败故事标题）
description（失败故事的详细描述）
image_url（失败故事的图片 URL，允许为空）
video_url（失败故事的视频 URL，允许为空）
created_at（失败故事创建时间）
表结构：
CREATE TABLE failures (
  id SERIAL PRIMARY KEY,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  description TEXT NOT NULL,
  image_url TEXT,
  video_url TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
failures_likes 表（用于记录用户点赞的失败故事）：
id（主键，自增）
failure_id（外键，关联失败故事）
user_id（外键，关联用户）
created_at（点赞时间）
表结构：
CREATE TABLE failures_likes (
  id SERIAL PRIMARY KEY,
  failure_id INT REFERENCES failures(id) ON DELETE CASCADE,
  user_id INT REFERENCES users(id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  UNIQUE(failure_id, user_id)
);
2.2 API 设计：
POST /failures：发布失败故事。
请求体：title, description, image_url, video_url（可选）
响应：返回发布成功的失败故事数据。
GET /failures：获取失败故事列表，支持分页和懒加载。
查询参数：page, limit（每页显示数量）
响应：返回失败故事列表，包含标题、描述、图片/视频等内容。
GET /failures/:id：查看单个失败故事的详细内容。
响应：返回失败故事的完整内容，包括图片/视频、描述等。
POST /failures/:id/like：点赞某个失败故事。
请求体：无
响应：返回当前点赞数。
POST /failures/:id/comment：用户对失败故事进行评论。
请求体：comment（评论内容）
响应：返回评论成功的消息。
2.3 前端设计：
展示墙页面（/wall）：
卡片布局：每个失败故事展示为一个卡片，包含：
标题
描述（简短内容）
图片/视频（可选）
点赞按钮（显示点赞数）
评论按钮（显示评论数）
**“查看详情”**按钮：点击进入失败故事的详细页面。
瀑布流布局：以宽卡布局展示失败故事，视觉上突出图片/视频，文字退为次要，增强视觉冲击力。
滚动效果：可考虑添加实时滚动的“失败故事”横幅（纯前端动画），使页面更加动态。
幽默化数据：在页面顶部展示全局统计（如“迄今共失败 N 次”，“今日最惨实验室”）。
匿名/作者切换：支持切换查看带头像版和匿名版，用户可以选择是否展示自己头像。
发布失败故事页面：
用户可以输入失败故事的标题、描述，选择上传图片/视频。
表单：提供标题、描述输入框，图片/视频上传功能。
提交按钮：提交失败故事后跳转到展示墙。
失败故事详情页面：
显示失败故事的详细内容（标题、描述、图片/视频）。
显示点赞数、评论区等互动元素。
点赞和评论：
点赞功能：用户可以为某个失败故事点赞，显示点赞数量。
评论功能：用户可以对失败故事发表评论，并看到已有评论。
2.4 社交分享功能：
为每个失败故事提供分享按钮，用户可以将失败故事分享至社交平台（如微信、微博等）。
分享方式：用户可以选择复制链接，使用系统原生分享（Web Share API）或分享至微博等平台。
微信分享：考虑到成本较高，建议先实现复制链接功能替代微信的直接分享。
3. 功能细节：
发布失败故事：
用户可以发布文字、图片和视频内容，分享实验中的搞笑失败经历。
展示失败故事：
页面展示所有用户发布的失败故事，采用卡片样式，按时间顺序展示，支持分页或懒加载。
点赞与评论：
用户可以点赞和评论每个失败故事，所有评论按时间顺序展示。
支持评论的点赞和回复，提升互动性。
社交分享：
每个失败故事提供分享功能，用户可以将失败故事分享至社交平台（如微信、微博）。
开发步骤：
Step 1：数据库表设计
创建 failures 表和 failures_likes 表，用于存储失败故事和点赞记录。
Step 2：API 开发
实现 POST /failures 用于发布失败故事。
实现 GET /failures 用于分页获取失败故事列表。
实现 GET /failures/:id 用于获取失败故事的详细内容。
实现 POST /failures/:id/like 用于点赞功能。
实现 POST /failures/:id/comment 用于评论功能。
Step 3：前端实现
创建 展示墙页面：以卡片形式展示失败故事，支持查看、点赞、评论。
创建 发布失败故事页面：允许用户输入标题、描述、上传图片/视频。
创建 失败故事详情页面：展示失败故事的详细内容和评论区。
Step 4：互动功能
添加评论和点赞功能，确保每个评论和点赞都能正确记录并展示。
实现分享功能，允许用户将失败故事分享到社交平台（如微信、微博等）。
验收标准：
发布失败故事：用户可以轻松发布自己的失败故事，并上传图片和视频。
展示墙：所有用户发布的失败故事都会展示在展示墙上，支持点赞和评论。
社交互动：评论和点赞功能正常，用户可以与其他用户互动。
图片和视频展示：用户的图片和视频能够正确显示，用户可以通过社交平台分享失败故事。
